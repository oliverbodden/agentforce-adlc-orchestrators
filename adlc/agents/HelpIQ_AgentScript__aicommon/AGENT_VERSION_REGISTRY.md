## 2026-05-15 update (HELPEXP-286 session — orphan-bundle blocker discovered)

**Major findings from analysis + deploy attempts:**

1. **v7 multiplier "regression" vs v4 was largely a welcome-only-fallback rate increase, not a prompt-driven regression.** Multiplier sub-agent `reasoning.instructions` is byte-identical between pre-v7-sync `.agent` and v7 (sha256 `25d78a0c22bd632d`, 3708 chars). Routing on multiplier-expected utterances is also nearly identical (only 2/26 unique utterances had any v4-vs-v7 routing variance, both trivial). The 8-15pp drop on coherence/completeness/conciseness/output_validation is driven by welcome-only response rate going from 47% (v4) to 58% (v7) — same prompt + same routing, just more cases where the agent emits the welcome message instead of synthesizing a real response after the action call. **On substantive responses (≥25w) v4 and v7 are essentially equivalent.** Welcome-only rate added to `config.json` as a guardrail.

### Pass rate comparison (4 runs, 999 cases each, all OOTB metrics)

| Metric | #1c Legacy v4 | #2b GPT4 v1 | #3 GPT5 v3 | #4 GPT5.2+new prompt |
|---|---:|---:|---:|---:|
| `topic_assertion` | 83% | 77% | 83% | 83% |
| `actions_assertion` | 73% | 83% | 88% | 87% |
| `output_validation` | 43% | 42% | 41% | **58%** |
| `completeness` | 46% | 49% | 44% | **75%** |
| `coherence` | **93%** | 90% | 83% | 91% |
| `conciseness` | 58% | 61% | 55% | **87%** |

**Reading (with GPT4 v1 now recovered):**
- **Action sequencing improves monotonically with the migration**: 73% → 83% → 88% (Legacy → GPT4 v1 → GPT5 v3). Migration is real for this metric.
- **Output quality is essentially flat from Legacy → GPT4 v1 → GPT5 v3 — none of the model upgrades alone help.** Across completeness/coherence/conciseness/output_validation, the three baselines sit in a 41-93% range with no systematic improvement. GPT4 v1 is in fact slightly better than GPT5 v3 on output quality with the same prompt (completeness 49 vs 44, conciseness 61 vs 55).
- **The new phased prompt + GPT5.2 (#4) drives the real output-quality gains:** completeness +26pp vs GPT4 v1, conciseness +26pp, output_validation +16pp.
- **Topic routing is at a ceiling around 83%** for all versions on Agent Script (router-level concern; GPT4 v1 anomaly at 77% likely router-classifier variance).

**Updated conclusion:** With 4-version data, the story is even sharper than the 3-version inference. **The prompt is the driver, not the model upgrade.** GPT4 v1 with the original prompt is functionally indistinguishable from GPT5 v3 with the same prompt on output quality. The +29pp / +29pp / +15pp gains in the GPT5.2+new-prompt run are not coming from going GPT4→GPT5.2; they're coming from going old-prompt → new-prompt. (One caveat: we still don't have GPT5.2 + original prompt, so we can't 100% rule out a synergy effect between GPT5.2 specifically and the new prompt.)

**Chain watcher detached process attempts failed** because Cursor's Shell tool kills child processes on teardown (even with `nohup`/`disown`/`start_new_session`). Monitoring is interactive: each user ping triggers a status poll. **Operational lesson:** the `/einstein/ai-evaluations/runs/{id}/results` endpoint takes ~5–7 min to return 5+ MB payloads for 999-case runs; CLI timeouts must be ≥ 10 min, not 90s.
